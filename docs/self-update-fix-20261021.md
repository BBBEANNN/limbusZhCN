# 相同版本重复安装与手动检查更新

用户报告 v1.5.1 更新完成后仍反复提示安装相同版本。对实际发布 APK 检查得到：

- Manifest 与 APK 内 `BuildConfig` 为 versionCode 7、versionName 1.5.1。
- `AppUpdateManager.prepareUpdate` 的最终 DEX 仍内联字符串 `1.5`，`inspectApk`
  仍内联安装版本号 `6`，导致把实际已安装的 7 当作新版。
- 更新模块的 class/DEX 时间早于新版 BuildConfig。此前只检查了 Manifest 版本，
  未检查消费这些常量的业务 DEX，漏掉了 Kotlin 增量编译产物不一致。
- 每次前台重新检查后，UI 将下载完成状态直接转为安装请求，使错误判断持续重现。

v1.5.2 的边界与修复：

1. 打开、返回前台、旋转不再联网检查。玩家点击“检查更新”才查询与准备安装包，
   准备完成仅显示按钮，再点击“安装新版”才打开系统安装器。
2. 所有升级判断与卡片版本显示都读取 PackageManager 实际安装信息。候选显示版本与
   安装版本号都须严格递增，不再把 BuildConfig 版本常量作为当前安装状态。
3. 缓存有效但系统已经同版或更高时，直接结束检查，不当作损坏缓存重下。
   下载完成、安装前、权限页和安装页返回均重新核对本地安装状态并移除过期请求。
4. 玩家在安装校验期间离开前台会使该次请求失效，返回时不自动重放。
5. 修复包干净重编，并检查最终 APK 的版本元数据和更新模块 DEX。继续沿用 v1.4 /
   v1.5.1 正式版证书，不清理应用、容器或游戏资源。

只修改宿主更新流程，不调整字体或翻译规则。

## 验证结果

- 干净重编成功，宿主 128 项测试中 125 通过、3 项既有跳过，无失败；更新策略新增
  同版、版本双递增、等待期间安装变化及长版本号回归。
- 最终 APK Manifest 为 8 / 1.5.2，更新模块 DEX 不再使用旧 `1.5` / `6` 版本门槛，
  调用 PackageManager 读取实际版本。MainActivity 无自动检查入口，下载成功不置安装请求。
- APK v2 签名及 16 KiB ZIP 对齐通过，与 v1.4/v1.5.1 正式版同证书；原生库与已验证的
  v1.5.1 版本逐字节一致。
- PHY110 / Android 16 已从 7 / 1.5.1 同签名覆盖到 8 / 1.5.2，保留数据；冷启动与
  Home 后返回均保持手动检查初始状态，没有系统安装器。手动点击后查询成功，显示
  “当前已是最新版本”，没有安装按钮或跳转（当时公开 latest 为较旧的 1.5.1）。
- APK SHA-256：`4233a4ad131dcc5f898e007ad787cdbcb3231bb506c28b0a3d4988a459b24200`。
